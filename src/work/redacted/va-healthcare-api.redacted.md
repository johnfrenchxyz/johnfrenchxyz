<h2 id="overview">Overview</h2>

<p>
  The platform provides APIs and a developer portal used by millions of users. When the project began, the portal had grown organically and required a unified design language.
</p>

<h2 id="problem">The Problem</h2>

<p>
  Documentation and onboarding were inconsistent. Developers faced differing conventions across API areas, and onboarding time-to-first-successful-call was high.
</p>

<h2 id="research">Research</h2>

<p>
  Research included interviews, usability testing, and benchmark analysis of leading developer portals. We identified distinct developer archetypes and used those to guide the redesign.
</p>

<h2 id="design-process">Design Process</h2>

<p>
  We ran six-week design sprints with open design reviews, introduced critique practices, and built a design system with documented components and tokens.
</p>

<h2 id="outcomes">Outcomes & Impact</h2>

<p>
  Post-launch outcomes included increased API adoption, improved accessibility compliance, and reduced support burden. Specific adoption figures and program names have been redacted.
</p>
